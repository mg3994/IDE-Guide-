# AMP HTML Guidelines for Blogger Posts (ideguide.blogspot.com)

This document specifies the mandatory AMP (Accelerated Mobile Pages) standards and structural guidelines for all blog posts generated for **IDE Guide** (https://ideguide.blogspot.com/).

---

## 1. Core AMP Requirements

All Blogger post HTML outputs generated by the agentic tools must comply with standard AMP HTML specifications:

1. **DOCTYPE Declaration**:
   Must start with `<!doctype html>`.

2. **AMP Root Tag**:
   The `<html>` tag must contain the `⚡` or `amp` attribute: `<html ⚡ lang="en">`.

3. **AMP JS Runtime**:
   Must include `<script async src="https://cdn.ampproject.org/v0.js"></script>` inside the `<head>` section.

4. **Charset & Viewport**:
   - `<meta charset="utf-8">`
   - `<meta name="viewport" content="width=device-width,minimum-scale=1,initial-scale=1">`

5. **Canonical Link**:
   Must include `<link rel="canonical" href="...">`.

6. **AMP Boilerplate CSS**:
   Must include the standard AMP boilerplate style block in `<head>`:
   ```html
   <style amp-boilerplate>body{-webkit-animation:-amp-start 8s steps(1,end) 0s 1 normal both;-moz-animation:-amp-start 8s steps(1,end) 0s 1 normal both;-ms-animation:-amp-start 8s steps(1,end) 0s 1 normal both;animation:-amp-start 8s steps(1,end) 0s 1 normal both}@-webkit-keyframes -amp-start{from{visibility:hidden}to{visibility:visible}}@-moz-keyframes -amp-start{from{visibility:hidden}to{visibility:visible}}@-ms-keyframes -amp-start{from{visibility:hidden}to{visibility:visible}}@-o-keyframes -amp-start{from{visibility:hidden}to{visibility:visible}}@keyframes -amp-start{from{visibility:hidden}to{visibility:visible}}</style><noscript><style amp-boilerplate>body{-webkit-animation:none;-moz-animation:none;-ms-animation:none;animation:none}</style></noscript>
   ```

7. **Custom Styling**:
   - All custom CSS MUST be inline within a single `<style amp-custom>` tag inside `<head>`.
   - Total CSS size must not exceed 75KB.
   - Do NOT use inline `style="..."` attributes on elements.

8. **Media Elements**:
   - Replace standard `<img>` tags with `<amp-img>` tags with explicit `width`, `height`, and `layout` attributes (e.g., `layout="responsive"`).

## 2. Content Structure for IDE Reviews & Guides

Every blog post must include the following standard sections:

1. **Title & Summary Header**:
   - High-catch title tailored for search and developers (e.g., *VS Code vs Cursor in 2025: Comprehensive IDE Review*).
   - Brief summary box highlighting the core target audience and verdict.

2. **Pricing & Licensing Overview**:
   - Clear distinction: **Free**, **Freemium**, or **Paid / Subscription**.
   - Price breakdown for individual developers vs teams.

3. **Key Features & Capabilities**:
   - Speed & memory usage evaluation.
   - AI assistance & integration capabilities.
   - Ecosystem / Extension support.
   - Key language support out-of-the-box.

4. **Pros & Cons Table**:
   - Objective comparison of advantages and drawbacks.

5. **Verdict & Recommendations**:
   - Guidance on who should use this IDE (e.g., beginners, enterprise teams, Rust developers, embedded systems engineers).

6. **Non-Sponsorship Disclaimer**:
   Every post MUST end with the explicit disclaimer:
   > **Disclaimer**: *IDE Guide is an independent technical publication. This content is not sponsored, endorsed, or affiliated with any software vendor or editor developer mentioned above. All reviews and assessments are based strictly on objective developer evaluation.*
