# Google Flow Video Generation Guidelines & Specification Standards

This document specifies the prompt engineering, framing, lighting, audio script, and structural standards for generating videos and YouTube Shorts using **Google Flow** and AI video creation tools for the **IDE Guide** channel ([@IDEguide on YouTube](https://www.youtube.com/@IDEguide)).

---

## 1. Core Mission & Tone
* **Channel:** IDE Guide ([@IDEguide](https://www.youtube.com/@IDEguide))
* **Blog Companion:** IDE Guide Blogger ([ideguide.blogspot.com](https://ideguide.blogspot.com/))
* **Tone:** Objective, technical, fast-paced, developer-centric, honest, unbiased.
* **Frequency:** 3 Videos/Shorts published daily alongside 3 AMP HTML blog posts.

## 3. Visual & Aesthetic Prompting Standards for Google Flow

When feeding prompts into Google Flow, adhere to these aesthetic guidelines:

### A. Lighting & Environment
* **Color Palette:** Dark Mode IDE themes (One Dark Pro, Catppuccin, Tokyo Night, Dracula) with vibrant syntax highlighting (cyan, magenta, electric amber, emerald green).
* **Lighting:** Studio dark room with subtle neon RGB background accent lights (teal and deep blue), soft directional key light on developer workspace/hands.
* **Atmosphere:** Modern, clean, high-tech software engineering studio aesthetic.

### B. Camera Angles & Movement
* **Macro / Close-up:** Ultra-sharp macro shot focusing on code cursor autocomplete, AI inline suggestions, keybindings, and terminal outputs.
* **Over-the-shoulder:** Over-the-shoulder view of a developer using a curved ultrawide monitor with the target IDE active.
* **Smooth Panning:** Slow horizontal or vertical pan across feature comparison charts, benchmark graphs, and extension marketplaces.

---

## 4. Scene-by-Scene Script & Specification Structure

Every video specification output for Google Flow must follow this 6-stage blueprint:

```
[Scene 1: Hook & Reveal] (0s - 5s)
- Visual Prompt: High-energy macro zoom onto IDE logo with code glowing on screen.
- Audio / Voiceover: Shocking or intriguing hook (e.g., "Is Cursor actually replacing VS Code in 2026? Let's break down the truth.")
- On-Screen Text: Bold title with IDE name and key question.

[Scene 2: Core Pros & Killer Features] (5s - 20s)
- Visual Prompt: Fast cuts of top 3 features (e.g., multi-file editing, speed benchmarks, AI index speed).
- Audio / Voiceover: Concise breakdown of what makes this editor outstanding.
- Overlay Graphic: Feature badges with checkmarks.

[Scene 3: Cons & Trade-offs] (20s - 35s)
- Visual Prompt: Visual demonstration of high RAM usage, paywalls, or plugin limitations.
- Audio / Voiceover: Objective, unvarnished truth about drawbacks and bugs.
- Overlay Graphic: Warning badge / red highlight callouts.

[Scene 4: Pricing Model (Free vs Paid)] (35s - 45s)
- Visual Prompt: Side-by-side pricing tier visual breakdown (Community Free Tier vs Pro Monthly Subscription).
- Audio / Voiceover: Clear breakdown of costs, usage limits, and freemium traps.

[Scene 5: Recommendation & Verdict] (45s - 55s)
- Visual Prompt: Developer smiling or nodding while selecting the best IDE for specific workflows (e.g. "Best for Rust", "Best for Solo Founders").
- Audio / Voiceover: Final verdict on who should use this editor and who should avoid it.

[Scene 6: Mandatory Disclaimer & Call-To-Action (CTA)] (55s - 60s)
- Visual Prompt: Screen displaying IDE Guide channel logo with links to ideguide.blogspot.com for the full AMP blog post.
- Audio / Voiceover: "Read our full deep-dive on ideguide.blogspot.com and subscribe to @IDEguide!"
- Disclaimer Overlay: "Independent evaluation. Not sponsored by any software vendor."
```
